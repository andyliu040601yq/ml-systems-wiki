# Group Speculative Decoding：公开文献排重与研究方案

**检索日期：2026-10-23**  
**定位：免训练、严格保持目标模型的 token 级采样分布、以算法贡献为主。**

## 一句话结论

在本次检索到的公开论文、预印本和专利中，**没有发现与下面这个具体方案完全一致的方法**：针对同一位置的多个草稿 token，构造一个可自适应细化的分组传输验证器，在严格保持目标分布的同时，给出其接受率与多草稿最优传输上界之间的可计算缺口界，并在推理时按计算预算停止细化。可以把它**暂定为有新颖性的研究假设**。但“分组”“组级拒绝采样”“多草稿最优传输”“层级无损验证”分别都已有公开工作；本结论不是绝对无人做过的证明，也不是顶会录用保证。

## 1. 要解决的问题

小模型在一个位置提出若干候选 token，目标模型已经通过一次 forward 得到概率分布。理想验证器会在保持最终输出分布完全等于目标模型的条件下，尽量输出某个候选，从而沿候选路径继续，一次目标模型调用产生更多 token。对固定的草稿生成分布，最大接受概率是一个最优传输问题。现有高接受率求解方法的额外计算可能过高；便宜的验证法又可能损失接受率。真正要优化的是**接受率增加能否超过验证器本身的时间成本**，最终看端到端 tokens/s。

## 2. 已公开工作与本方案的边界

- **SpecTr（NeurIPS 2023）**将多候选接受写成成员成本最优传输，并给出高效近似；因此“多个草稿 + 最优传输”不是新贡献。[论文](https://arxiv.org/abs/2310.15141)
- **SpecHub（EMNLP 2024）**研究高效多草稿验证及其理论保证；因此必须把它作为速度和接受率基线。[论文](https://aclanthology.org/2024.emnlp-main.1148/)
- **Towards Optimal Multi-draft Speculative Decoding（ICLR 2025）**给出最优接受率分析，指出无放回采样是重要基线。[论文](https://proceedings.iclr.cc/paper_files/paper/2025/hash/0907335ecf28faf15be54485dbcbe70e-Abstract-Conference.html)
- **Global Resolution（2025 预印本）**将独立同分布多草稿的最优传输化为较小的凸优化问题，并可调求解精度；因此“逐步逼近最优”单独不足以构成新意。[论文](https://arxiv.org/abs/2511.15898)
- **Qualcomm 公开专利 WO2024205726A1（2024）**明确写到汇总组概率、组级拒绝采样及组内 token 选择，并提到多条候选序列；因此“先选组再选 token”也不是新贡献。[专利](https://patents.google.com/patent/WO2024205726A1/en)
- **Grouped Speculative Decoding for Autoregressive Image Generation（ICCV 2025）**用动态聚类接受视觉 token；其目标是视觉质量，不能把其宽松接受直接当作文本模型的精确采样。[论文](https://arxiv.org/abs/2508.07747)
- **Hierarchical Speculative Decoding（2026）**提出严格保持分布的层级验证，并可用于多草稿场景；因此“层级无损验证”不是新贡献。[论文](https://arxiv.org/abs/2601.05724)
- **UniVer（2026）**将多步与多草稿树验证统一到条件最优传输；如果扩展到树结构，必须直接与之比较。[论文](https://arxiv.org/abs/2605.04543)

**排重判断：**最接近的交叉区域已经很拥挤。当前尚未找到同时具有“自适应 token 分区、运行时可计算的最优接受率缺口界、严格目标边际、低成本停止规则”的公开方法。这个交集才是待检验的新颖点，不能把标题里的 *group* 当作新颖点。

## 3. 具体算法假设：Certified Adaptive Group Transport（暂名）

先限定最容易证明和实现的**单位置、多草稿**问题。设目标分布为 `p(x)`，草稿候选列表为 `D=(d1,...,dk)`，其生成机制的联合分布为 `Q(D)`。验证器输出分布 `K(x|D)`，须满足：

`对每个 x：sum_D Q(D) K(x|D) = p(x)`。

接受率为 `A = sum_D Q(D) sum_{x in unique(D)} K(x|D)`。这一约束说明：只要最终 token 的边际仍是 `p`，就可以改变“从哪份草稿接受”的联合选择；单纯提高组接受率而忽略组内校正则不保证精确性。

拟研究的路线：

1. **离线定义可快速计算的初始分区。**例如依据草稿模型概率、候选出现频次及 token 概率区间建立少量组；这一步不需要目标模型额外 forward，也不需要训练。
2. **目标模型一次验证后，计算每组的目标概率质量和草稿可覆盖质量。**先解低维组级概率质量分配问题；分组只压缩求解规模，不改变目标模型输出。
3. **针对瓶颈组进行自适应细化。**用组内候选覆盖与目标质量的不匹配估计该组可能损失的接受率；优先拆分预计收益最大的组，并按预算停止。
4. **构造严格的 token 级分配与剩余采样。**需要给出实际可执行的 `K(x|D)`，证明它非负、归一化且满足上面的边际约束。组级质量守恒本身不足以证明这一点；这是算法的核心难题。
5. **证明可计算的接受率缺口界。**若 `U` 是同一草稿机制下的最优接受率上界，算法给出 `L=A` 及可计算 `U-L`。停止时报告该差距，而不只是宣称“接近最优”。界必须包含分组压缩造成的误差。

这里的“自适应”发生在**目标概率已经由既有验证 forward 得到以后**。若额外再跑一次目标模型才能分组，通常会吞掉潜在提速。

## 4. 为什么这个问题可能有论文价值

若能同时得到：①可实现的严格分布保证；②非平凡的接受率缺口界；③比已有验证器更好的“接受率增益 / 验证耗时”前沿；④真实模型上的端到端提速，那么贡献是明确的算法，而非只调整树宽或换一个聚类指标。尤其要与 Global Resolution 的可调精度求解区别开：本方法必须证明**分区结构确实降低了实际耗时，并给出可用的停机证书**。如果只能提高离线接受率、不能提高 tokens/s，就不应继续包装为推理加速论文。

## 5. 最小可行验证与终止条件

**阶段 A：无需 GPU 的概率实验。**先在小词表上枚举草稿列表，求精确最优传输作上界。实现标准多草稿验证、固定分组、拟议自适应分组。检查每个 token 的精确边际，并画接受率对验证器耗时曲线。若无法构造满足边际约束的有效验证器，或自适应分组没有优势，立即停止这个方案。

**阶段 B：真实模型概率回放。**选至少两组公开的小模型/目标模型组合，从代码、普通文本及推理提示中采集 `p`、`q` 和草稿列表。在同一批概率与同一草稿上比较，固定 `k`、采样温度、候选生成规则和验证器计算预算；报告接受率、缺口界松紧度、验证器时间。避免把换草稿模型产生的收益算到验证算法上。

**阶段 C：端到端推理。**先做单请求、低并发、不同温度与草稿数的延迟和 tokens/s；再检查小批量。计入草稿生成、目标 forward、分组求解、CPU-GPU 同步及 fallback 的全部时间。对照目标模型直接解码、常规 speculative decoding、SpecTr、SpecHub，以及可复现的 Global Resolution 配置；树场景再增加 UniVer/HSD。无须训练任何新模型。

**继续投入门槛：**严格分布证明成立；真实概率上对强基线有稳定的接受率—验证耗时前沿改进；端到端至少在一个清晰且重要的工作区间实现可复现提速。若这三项缺一，不建议租更多 GPU 扩大实验。

## 6. 当前判断与局限

**建议作为研究题目立项做小规模验证，但不建议现在就宣称“完全无人探索”或“顶会稳发”。**本次公开资料排重支持的是一个窄而具体的研究假设；最大的技术风险是严格 token 级校正可能使低维分组方案失去效率，最大的论文风险是与已有层级验证或可调精度最优传输相比只剩实现细节。下一步最关键的是先写出 `K(x|D)` 的可执行构造和证明，再做小词表实验。
